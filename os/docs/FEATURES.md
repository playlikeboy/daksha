# OpenFuse feature inventory

The native and web agent core runs locally. This inventory describes the current implementation and remaining extensions. Live providers and optional infrastructure require separate configuration and validation.

## Implemented coverage

| Area | Current implementation | Remaining extension |
| --- | --- | --- |
| Chat / delegated work | Native CopilotKit chat, direct mail and time-bounded primary calendar reads, durable tasks and confirmed outcomes | Live model/provider acceptance testing |
| Ideas / personal context | Source-backed mail/goal rules, accept/edit/dismiss, identity, editable/forgettable memories | Broader model-derived cross-connector suggestions |
| Goals / Tracking | Milestones, recurring watches, observations, retry/backoff, pause and cancellation | Adaptive long-term planning and calendar-driven reminders |
| Browser | Persistent Chromium, public page reads, snapshots, console takeover, PDF downloads | Autonomous interactive booking and per-person VM orchestration |
| Linux computer | Nonroot Docker container, bounded bash/Python/Node/git commands, saved output and exit receipts, persistent workspace files, text editing, PDF import/export | Interactive terminal, desktop apps, controlled egress, disk quotas and stronger VM isolation |
| Gmail / Calendar | Google OAuth; complete threads; saved drafts; calendar/event CRUD with reviewed versions | Live Google acceptance, recurrence editing, other connectors |
| PDF job | Durable import, typed input request, filled-copy preview, reviewed reply, receipt | OCR/scanned forms and additional PDF field types |
| Generated results | Plans/reports/comparisons, finance CSV metrics, and scripts in the private Linux workspace | Managed tool installation/versioning and audio generation |
| Debo journal / What Debo knows | Journal (write, find, edit, delete), questions answered only from the person's entries with source chips that open the entry, memories from hosted Mem0 each linked to its entry with fix and forget, activity record. Agent tools `search_my_journal`, `ask_my_life` (read) and `add_journal_entry` (saves at once, for today or a named day, and returns a chip that opens the entry; since 14 November 2026, at the owner's request, changes inside Debo need no review, while deleting and anything that leaves Debo still do). Uses the shared `@debo/brain`, `@debo/db`, `@debo/memory` packages; routes under `/api/debo`. The writing box keeps a draft on the device (browser storage, or a file on the phone), shows a word count and lets the person change the day; Ctrl or Command with Enter saves on the web | Live acceptance against a real Debo database |
| Journal recordings | Voice notes and videos: record in the browser or in the phone app (`expo-audio`, `expo-camera`), or add a file, listen or watch before saving, upload straight to a private R2 bucket (in parts for big files), words written in the background by Workers AI Whisper with timed segments, language and a file fingerprint, searchable and cited like a written entry ("Voice note, 11 November"), "Try again" when the words fail, delete removes the file, "Download my data" lists each recording with a 24 hour download link. Speak: dictate into the text in short clips. Limits: 200 MB, 60 minutes, 4 hours and 40 recordings a day. See [JOURNAL-MEDIA.md](JOURNAL-MEDIA.md) | Run against real R2 and Workers AI; phone recording and playback run on a real phone; dictation on the phone (the keyboard's microphone is used instead); Hindi and mixed speech quality |
| Journal entry pages and recorder | Each entry has its own page at `/journal/<slug>-<id>` (the slug follows the title, like chat addresses; the id is the truth; works on reload and from `debo://journal/...`; tapping an entry in the list opens it). Written: a reading layout, "Happened on", change and delete. Voice note: play, a waveform that is the scrub bar (the real sound on the web up to 30 MB, else bars where words were said), 15 seconds back and forward, speed, download, and the words with times (pressing one plays from there). Video: large player, words beside it on wide screens and under it on phones, same jumping. Voice call: a conversation (you and the assistant, with its face), length and date. Every page: what Debo learned from it (fix, forget), and "Similar entries" from `GET /api/debo/entries/:id/similar` (up to five, closest first, from the stored embeddings, owner only, never itself, no model call). Skeleton while loading, Try again on errors. The full-screen recorder: big timer, live level (or camera), pause and carry on, stop, throw away (asks first), flip camera, microphone and camera choice on the web, title, the day, review with record again, save with progress; the screen stays on and leaving mid-way asks first. See [JOURNAL-MEDIA.md](JOURNAL-MEDIA.md) | The similar-entries SQL has not run against a real Neon database (tests use a fake); phone recorder and players not run on a device; pausing a video on the phone; a note typed with a recording |
| Voice and role-play | Talk popup (microphone button in the chat box, or /talk), which can be minimised to a small bar above the tabs while the call goes on (the bar always shows the microphone, with Mute, End and Review for anything waiting for a tap; iOS background audio is set; on Android a "Debo is listening" notification with an End button keeps the call going in the background, not yet run on a phone; see [VOICE.md](../../docs/VOICE.md)): the same agent and tools as chat, calls saved as chats and, always, as a text source in the journal ("Voice call, 14 November": each turn saved as it is said, read once when the call ends or later if the app never says so, memories only from what the person said, deleted with the normal Delete, in export and account deletion; see [VOICE.md](../../docs/VOICE.md)), risky actions (outside Debo, and deleting) only as on-screen reviews, shown as an Approve / Not now card inside the Talk popup; pressing the face at the top of the app starts a call (the consent text shows the first time on a device); voice and speed are chosen per person in "How she talks and what she knows" (voice, personality, notes; four voices; no sample button); a role Debo keeps until stopped (Apps screen, A role for Debo), a feeling in her voice | Not tried with a live call or a phone; voice minutes are not counted in usage |
| People and daily check-in | "People in your life": name, relation, birthday, special days and notes, saved by Debo from chat or a call (`note_person`, `list_people`) or by the person in the app card (see, fix, add, remove); up to 40 people and the next week's birthdays are given to the model as data; `daily_checkin` tool and `GET /api/checkin?tz=` build a short brief in the person's time zone (the app sends `X-Time-Zone` on every request; the last one is kept as a `time-zone` record, and the prompt says "Today is <date> in <zone>") from people, waiting tasks, active goals and the last week's entries (with source labels); stored as `people` rows, in export and account deletion; see [PLAN-daily-companion.md](../../docs/PLAN-daily-companion.md). Reminders on their own (`companion-jobs.ts`, run by the 60-second upkeep loop): birthdays and special days the day before at 18:00 and the morning of at 08:00 (on unless turned off), an opt-in morning check-in at a chosen time (default 08:00, sent within three hours of it) posted as a "Good morning" update with names and counts only, and reminders the person asked for; once each (idempotent keys), in the person's saved zone, never 22:00 to 07:00. Promises found in a saved or edited typed entry (one model call, `findPromises` in `@debo/llm`) become Ideas of kind `promise` with the entry as evidence; "Remind me" makes a `reminders` row, "Dismiss" puts it away; deleting the entry deletes both. Settings card "Reminders and check-in" in "How she talks and what she knows" (`companion-settings` row; `/api/companion/*`) | Not tried with a live model; promises in voice notes and calls are not looked for; mood over time, lists, habits |
| Notifications | Durable in-app inbox, source-linked change alerts, restart reconciliation. The chat's update card shows every unread update, with or without a task (reminders, birthdays, the check-in), with Dismiss. "Send me reminders" per device: in a browser, web push (`web-push`, VAPID keys `DEBO_OS_VAPID_PUBLIC_KEY` / `DEBO_OS_VAPID_PRIVATE_KEY`; without both the switch is hidden; `public/sw.js` only shows the push and has no fetch handler; one `push-subscriptions` row per browser, known push services only, title only, export without keys, gone devices forgotten on 404/410); on the phone, the next 50 reminders and birthdays (`GET /api/companion/upcoming`) are held as local notifications (`debo-device-reminders.native.ts` over `debo-reminder-alerts.native.ts`), refreshed when the settings card opens, when it is turned on and when a promise is accepted; signing out removes them | Web push not tried against a real push service; phone notifications not run on a device; APNs/FCM remote push (needs Firebase and Apple push credentials) |
| Connectors | Searchable capability/status catalogue, Google connection, browser worker, apps connected through Composio (reads run, changes wait for your yes; see [CONNECTORS.md](CONNECTORS.md)) | Plaid, health, Instagram, WhatsApp and partner APIs |
| Your own tool servers (MCP) | Add a server by https address with a secret, a custom header, or a sign-in on the server's own page (OAuth: dynamic registration, PKCE S256, signed single-use state, encrypted tokens refreshed early or on a 401, Sign in again and Sign out). Card "Composio: connect all your apps at once" adds the person's own Composio account by sign-in or API key. Every change waits for a yes; see [CONNECTORS.md](CONNECTORS.md) | Not tried with a real Composio account; sign-in services that need Debo registered by hand; SSE-only servers |
| Pictures | `make_image` in chat and on calls: a picture from a description (optional look: photo, illustration, watercolor, sketch, 3d, pixel art), shown in the chat as a card and again whenever the thread is opened (a fresh signed link each time, `GET /api/images/:id`). Drawn by Cloudflare Workers AI FLUX.1 schnell through the Worker's AI binding (`ai.internal/image`) or the REST API, square only, 20 a day per person; or by the person's own OpenRouter picture model (square, wide or tall, no Debo limit). Kept in the private R2 media bucket under the person's folder with an `images` record (prompt, when, which service), in export, deletable one by one (`DELETE /api/images/:id`) and with the account. A word check refuses sexual pictures and fakes before any service is asked; the service has its own filter. Saved at once with no review (decision 28) | Not tried against real Workers AI or OpenRouter; no picture list screen yet; no editing of a picture |
| Your own AI keys | Settings, "How she talks and what she knows", folded "Advanced: use your own keys": an Anthropic key (with a Claude model) and an OpenRouter key (with a chat model that must support tools, and a picture model). Each key is checked with one cheap call before it is saved (Anthropic Models API, OpenRouter `/key` and the model's endpoints), stored encrypted with `TOKEN_ENCRYPTION_KEY` as a `credentials` record, never sent back (only "ends in 1234"), never logged, only "key set" in export, deleted on Remove and with the account. With an Anthropic key, chat, calls, delegated tasks and journal answers run on it, and the journal's daily limit does not apply; otherwise an OpenRouter chat model is used (OpenAI Chat Completions through `@tanstack/ai-openai`). See decision 32 | Not tried with real keys. Voice hearing and speaking (LiveKit, Deepgram, Cartesia) stay on Debo's account; Mem0, Composio (already its own card), the Neon AI Gateway and Workers AI have no own-key option |
| Changing settings by asking | In chat and on calls, saved at once with no review (decision 28, decision 33; `apps/server/src/settings-tools.ts`): `update_talk_settings` (voice by name, speed 0.8 to 1.3, mood, how much she says, language, and adding a line to "Things she should always know"; it never replaces or wipes the notes), `update_identity` (the assistant's name, tone and character; when only the character changes, a name the person chose is kept and a character's name follows the new character), `update_reminders` (birthday reminders, the morning check-in and its time, 07:00 to 22:00 only). Each reuses the store and checks of its settings screen and is scoped to the owner. `open_screen` gives a card with a button for one screen from a fixed list (`packages/domain/src/screens.ts`: settings, people, reminders, own keys, apps, what Debo knows, journal, activity, goals, files, calendar, computer, face builder, your own people, adding files); the app maps each to a sheet or section (`apps/mobile/src/screen-links.ts`), and one it does not have yet shows "isn't in this version of the app yet". On a call she says where to find it. Chat shows a card with what changed and "Open settings"; an open settings sheet or reminders card loads again after a change made while the card was on screen | Not tried with a live model or on a phone. Changes made on a call show in open settings only after they are reopened (the name and character follow within a few seconds through the app's refresh). Face builder and your own people screens are not in this branch, so those cards show the "not in this version" note until they are |
| OpenBot | Disabled adapter with pinned protocol/identity tests | Live session bridge, routines and computer backend wiring |

The Linux computer is disabled until configured on the server and has no network access. It is a single-owner container with a persistent `/workspace`, separate from the browser worker; see [computer setup and limits](COMPUTER.md). It is not a graphical desktop or a full OS VM.

Model chat can read the connected primary calendar for an explicit time range of up to 366 days. Missing dates or time zones need clarification. A reply uses at most 20 events and bounded event text; partial results and connection failures are reported. All-day dates keep their calendar time zone and exclusive end date. Calendar changes still require action review. The sample agent's canned replies do not provide this model tool.

The implementation and validation details are in [VERIFICATION.md](VERIFICATION.md). Planned extensions are not claims of current support. Priorities are tracked in the [roadmap](../ROADMAP.md).
